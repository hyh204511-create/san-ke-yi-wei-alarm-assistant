# 三客一危平台视频分析与需求信息梳理

视频文件：`ebf21d6305723e06a28206521e65742e_raw.mp4`

分析日期：2026-06-18

## 一、视频中确认的平台事实

视频顶部显示平台名称为：

> 湖南省交通运输“三客一危”智能监管平台

平台不是一个简单报警列表，而是一个综合监管后台，至少包含以下能力：

- 数据看板
- 车辆监控
  - 实时视频
  - 轨迹回放
  - 录像回放
- 报警事件处理 / 预警相关模块
- 报警中心
- 报警查询
- 备案协办
  - 上报交办
  - 督办查询
- 驾驶员管理
- 车辆档案 / 车辆管理
- 设备相关管理
- 报表中心
- 系统设置

这说明 AI 助手不应被设计成单独替代平台，而应作为“省平台上方的处置自动化层”。

## 二、与需求直接相关的关键画面

### 1. 报警提示弹窗

视频约 4 分 20 秒左右，右下角出现原生平台弹窗：

- 标题：报警提示
- 展示报警数量
- 展示车牌号，例如 `湘A测001(黄)`（合成示例）
- 展示报警类型，例如疑似“生理疲劳”
- 展示报警时间
- 有“查看报警”按钮
- 可收起 / 关闭

对 AI 助手的含义：

- AI 需要监听这个报警弹窗。
- 弹窗是实时报警入口之一。
- 不能只监听列表刷新，还要监听弹窗出现、消失、收起、点击“查看报警”后的页面跳转。
- 弹窗字段应进入报警事件模型：车牌、报警类型、报警时间、弹窗出现时间、是否点击查看。

### 2. 实时视频与车辆详情

视频约 2 分 30 秒至 5 分钟，多次出现实时视频页面：

- 左侧为企业 / 车辆树
- 中间为地图
- 右侧为四宫格视频
- 下方 / 右侧有车辆实时信息面板
- 车辆信息包含：
  - 车牌号
  - 车辆颜色
  - 车辆版本 / 年份
  - 驾驶员
  - 所属机构 / 所属企业
  - 当前速度
  - ACC 状态
  - 定位方式
  - 位置
  - 定位时间
  - 行驶时长 / 停车时长
  - 备注信息

视频画面包含多个通道：

- 车内驾驶员画面
- 车内乘客 / 车厢画面
- 道路前向画面
- DSM / ADAS 摄像机画面
- 空画面 / 无视频画面

对 AI 助手的含义：

- AI 判断驾驶员是否纠正，不能只看报警截图，还要持续看实时视频。
- 需要识别视频通道类型：驾驶员通道、道路通道、车厢通道、ADAS / DSM。
- 需要记录证据是否可用：有画面、黑屏、无视频、摄像头遮挡、画面延迟。
- 对讲干预前，需要拿到车辆、司机、企业、位置、速度和报警类型。

### 3. 文字下发与语音对讲入口

实时视频页面右侧视频区域下方可见操作入口：

- 文字下发
- 语音对讲
- 批量文字下发
- 停止
- 刷新
- 全屏

对 AI 助手的含义：

- AI 干预路径应该优先围绕这两个入口：
  - 文本提醒
  - 语音对讲
- 第一阶段不要假设有后端 API。更现实的方案是：
  - 页面自动化点击“文字下发”
  - 页面自动化点击“语音对讲”
  - 使用固定话术或预审模板
  - 保存下发 / 对讲动作截图和时间线
- 语音对讲必须有失败兜底：按钮不可用、设备离线、通道占用、麦克风权限失败、司机无回应。

### 4. 报警明细弹窗

视频约 0 分 57 秒出现“明细”弹窗，内容包括：

- 处理流程
  - 上报
  - 处理中
  - 上传证据
  - 报警复核
  - 上传证据
  - 上传证明
- 报警证据
  - 驾驶员 / 车内截图
  - 视频帧
  - 速度曲线
  - 路段 / 定位相关曲线
- 图表信息
  - 速度（公里/小时）
  - 踩板 / 踏板百分比
  - 定位相关指标

对 AI 助手的含义：

- 平台已经具备报警证据链，不需要 AI 重新造证据。
- AI 要做的是自动抓取、归档、摘要、判断是否可申报。
- 申报材料应包含：
  - 报警截图
  - 视频帧
  - 速度曲线
  - 处理流程节点
  - 平台处理状态
  - AI 分析依据
  - 人工确认记录

### 5. 证据中心 / 报警证据弹窗

视频约 6 分 01 秒出现“证据中心”类弹窗：

- 左侧展示报警基础信息
- 中间 / 右侧展示多路视频证据
- 下方展示速度曲线
- 左侧包含地图 / 报警图片
- 背景是报警列表
- 弹窗外仍能看到“报警提示”浮层

对 AI 助手的含义：

- “查看报警”后可能进入证据弹窗，而不是独立页面。
- AI 需要支持弹窗层级识别。
- 证据采集不能只依赖 URL 路由，需要能识别弹窗 DOM。
- 需要保存弹窗截图作为证据采集成功的凭证。

### 6. 督办 / 协办 / 处理记录

视频约 7 分 28 秒出现督办详情页面，能看到：

- 督办信息
  - 督办编号
  - 督办事项
  - 当前状态
  - 限期时间
  - 督办方式
  - 督办类型
  - 督办发起人
  - 联系电话
  - 发起时间
  - 所属机构
  - 督办内容
- 处理信息
  - 处理人
  - 联系方式
  - 处理时间
  - 处理内容
- 全部附件
- 处理流程
  - 发起督办
  - 督办处理
  - 处理审核

对 AI 助手的含义：

- 报警处理记录不应只是“已处理”三个字。
- 需要生成结构化处理记录：
  - 处置动作
  - 处置人
  - 联系方式
  - 处置时间
  - 处置内容
  - 附件 / 证据
  - 流程节点
- 如果司机未纠正，电话或短信通知企业负责人后，通知结果也应进入类似处理记录。

### 7. 驾驶员管理与企业联系人信息

视频约 8 分 04 秒出现驾驶员管理页面：

- 姓名
- 电话
- 所属机构
- 头像
- 身份证号
- 身份证正反面
- 操作按钮：
  - 审核
  - 提交审核
  - 修改
  - 下发车辆
  - 操作记录
  - 停用
  - 删除

视频约 8 分 40 秒出现车辆档案详情：

- 车牌号
- 车牌颜色
- 车辆类型
- 车辆经营范围
- 车主 / 负责人
- 负责人电话
- 终端编号
- 所属行业
- 车辆状态
- 是否营运
- 车辆定位 / 终端绑定记录

对 AI 助手的含义：

- 通知企业负责人不能只依赖报警页，需要从企业 / 车辆 / 驾驶员档案补全联系人。
- 联系人数据可能来自：
  - 车辆负责人
  - 企业负责人
  - 驾驶员电话
  - 企业紧急联系人配置
- 必须记录“通知给谁、号码是什么、来源是什么、是否接通、是否确认”。

## 三、与“AI 对讲干预”相关的闭环流程

基于视频观察，建议把真实闭环定义为：

```text
平台报警提示弹窗出现
  ↓
AI 读取报警弹窗字段
  ↓
点击“查看报警”或定位到报警列表记录
  ↓
读取报警详情、车辆、司机、企业、位置、速度、视频通道
  ↓
打开实时视频 / 报警证据
  ↓
AI 判断报警类型与风险等级
  ↓
触发文字下发或语音对讲
  ↓
持续观察视频与报警状态
  ↓
若司机纠正
    记录：已干预、已纠正、证据、时间线
  ↓
若司机未纠正 / 无回应 / 高风险
    电话或短信通知企业负责人
  ↓
记录企业通知结果
  ↓
生成报警处置记录、证据包、台账
```

- 报警 ID
- 报警类型
- 报警来源：弹窗 / 列表 / 详情页
- 车牌号
- 车牌颜色
- 驾驶员姓名
- 企业 / 所属机构
- 报警时间
- 平台接收时间
- 报警地点
- 当前速度
- ACC 状态
- 定位方式
- 行驶 / 停车状态
- 风险等级
- 平台处理状态

- 视频通道数量
- 可用通道
- 失效通道
- 驾驶员画面是否可见
- 道路画面是否可见
- 是否黑屏 / 无视频 / 遮挡
- 报警截图
- 视频帧
- 速度曲线
- 地图位置截图
- 证据弹窗截图

### 干预动作字段

- 文本下发内容
- 文本下发时间
- 文本下发结果
- 语音对讲话术
- 语音对讲开始时间
- 语音对讲结束时间
- 对讲通道是否可用
- 驾驶员是否回应

### 企业通知字段

- 企业名称
- 联系人姓名

- 通知方式：电话 / 短信 / 企业微信
- 通知时间
- 是否接通
- 是否确认

- 通话录音或短信回执

- 处置结束时间

- 证据附件
- 企业通知记录
- 处理内容摘要
- 处理流程节点
- 是否闭环

## 五、对当前产品原型 / PRD 的修正建议

### 1. 报警入口要从“列表优先”改为“弹窗优先 + 列表兜底”

视频中右下角报警提示弹窗非常明确。AI 应优先监听弹窗，再用报警列表兜底。

### 2. 对讲干预不应设计成抽象按钮，应贴近平台入口

原型里应明确展示：

- 文字下发
- 批量文字下发
- 语音对讲
- 停止
- 刷新
- 全屏

并记录每个动作的成功 / 失败。

### 3. 司机是否纠正必须基于“干预后持续观察”

不能在语音对讲后立刻标记成功。

建议增加：

- 干预后观察窗口，例如 30 秒 / 60 秒 / 120 秒
- 报警是否持续
- 视频行为是否纠正
- 是否再次报警
- 是否需要升级通知企业

### 4. 企业通知需要绑定联系人来源

视频显示驾驶员管理、车辆档案里都有电话和负责人信息。电话通知不能只存一个号码，要记录号码来源。

### 5. 记录生成要对齐“督办/处理信息”结构

处理记录建议至少包含：

- 处理人
- 联系方式
- 处理时间
- 处理内容
- 附件
- 处理流程

这比单纯“报警已处理”更接近平台实际。

### 6. 证据包必须支持弹窗截图和多路视频

视频中证据中心是弹窗形式，且视频多路并存。AI 证据包应保存：

- 弹窗截图
- 多通道视频截图
- 地图截图
- 速度曲线截图
- 报警处理流程截图

## 六、最关键的产品判断

这个项目的核心不是“AI 能不能说话”，而是：

> AI 能不能在三客一危平台原生报警弹窗出现后，稳定识别报警、打开证据、使用平台已有文字下发和语音对讲入口进行干预，并在司机未纠正时通知企业负责人，最后生成与平台处理记录结构一致的可追溯台账。

因此第一阶段的最小可验收闭环应调整为：

```text
报警弹窗监听
→ 查看报警
→ 读取车辆/司机/企业/视频/位置/速度
→ 文字下发或语音对讲
→ 干预后观察
→ 未纠正则通知企业负责人
→ 生成处理记录和证据包
```

不建议第一阶段继续扩展完整老板看板、复杂规则配置和全量报警类型覆盖。
