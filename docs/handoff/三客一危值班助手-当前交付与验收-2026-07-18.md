# 三客一危值班助手：当前交付与验收

> **2026-07-18 历史交付快照。** 当前产品逻辑与交付入口见 [产品逻辑规划 V2](../product/三客一危值班助手-产品逻辑规划-v2.md) 和 [阶段实施文件说明](../deliverables/值班助手阶段实施文件/README.md)。本文中的本机导出不是目标产品的正式日报/月报或敏感证据包流程。

## 1. 当前可交付范围

本仓库当前提供两个可独立运行、可组合联调的本机组件：

1. `browser-extension/`：Chrome/Edge Manifest V3 值班辅助扩展及本机 JSONL 采集服务。
2. `sandbox/`：Django 5.2 本地契约沙箱、平台风格测试页面、已知接口和异常场景。

已形成“白名单 Fetch/XHR 采集 → 标准报警事件 → 跨接口归并与去重 → 版本化规则决策 → 演练/本机沙箱固定语音动作 → 台账与审计”的本地闭环。

沙箱只模拟当前文档中已知的接口路径、字段和交互，不代表真实省平台完整契约。真实平台仍需校准鉴权、请求体、响应字段、DOM、车辆在线状态和动作回执。

## 3. 首次沙箱闭环

1. 从页面顶部下载 `audio-sandbox-v1.wav` 和 `sandbox-rules.json`。
2. 在插件设置中填写音频资产 ID `audio-sandbox-v1`，选择 WAV，勾选“已经业务方确认”，再导入。
3. 导入 `sandbox-rules.json`。
4. 将运行模式切换为“沙箱动作”。
5. 点击页面顶部“触发新报警”。
6. 在插件面板核对标准事件、规则版本、动作状态和台账。
7. 切换“对讲失败”“字段缺失”“响应结构变化”等场景验证兜底；结束后点击“重置”。

沙箱对讲只接受固定本机地址、固定测试音频、已知合成报警及其对应合成车辆。它不会连接真实车辆。

## 5. 安全边界

- 默认模式是 `DRY_RUN`。
- `SANDBOX` 只调用 `http://127.0.0.1:18080/sandbox/api/intercom/simulate`。
- `LIVE` 具备规则、音频、模式、白名单和调用链验证闸门，但生产 HTTP/WebSocket 适配器尚未实现，当前固定阻断。
- 未命中、冲突、字段不足、音频无效、动作失败或结果不确定统一转人工。
- 规则导入失败时保留旧版本；非空风险条件在语义确认前会被拒绝，不会被静默忽略。
- CSV 默认脱敏，完整 JSON 只用于授权本机核查。

## 6. 真实平台联调前置条件

以下条件全部具备后，才能开发并验证生产对讲适配器：

1. 项目负责人和客户对真实动作的明确授权。
2. 具有对讲权限的测试账号。
3. 明确的测试车辆白名单。
4. 已确认规则、固定话术和固定音频。
5. 对讲启动、WebSocket、保活、关闭接口的真实请求与回执证据。
6. 车辆离线、无权限、超时、断线和关闭失败的受控测试窗口。

在这些证据缺失时，不得把沙箱成功回执表述为真实平台对讲已完成。
