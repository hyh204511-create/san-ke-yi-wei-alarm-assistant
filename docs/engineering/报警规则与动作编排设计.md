# 报警规则与动作编排设计

> 产品 V2 调整：当前运行时的 `AUTO_VOICE` 等动作枚举属于已实现的过渡模型。目标产品将“处理策略”和“响应渠道”分离，支持固定文本、固定语音及组合编排；规则配置人与审核人必须职责分离。详见 [产品逻辑规划 V2](../product/三客一危值班助手-产品逻辑规划-v2.md)。

## 1. 设计目标

规则是可变业务数据，不写死在采集、去重和对讲代码中。运行时以版本化JSON为权威格式；业务方Excel在获得正式模板后转换、校验并生成新的JSON版本。

原始抓取、标准事件、规则判断和动作执行分层保存，避免把一次接口响应直接当成一次处置。

## 2. 领域对象

| 对象 | 作用 |
| --- | --- |
| `Capture` | 一次白名单请求/响应的脱敏证据 |
| `AlarmEvent` | 跨接口归并后的业务唯一报警 |
| `RuleSet` | 一批同时生效的规则及版本说明 |
| `Decision` | 某事件在某规则版本下的确定性判断 |
| `ActionAttempt` | 一次演练或真实对讲尝试及结果 |
| `LedgerRow` | 面向值班查询和导出的扁平记录 |

报警ID、车辆ID等长标识全程使用字符串。

## 3. 规则结构

```json
{
  "schemaVersion": 1,
  "version": "2026-07-18-v1",
  "status": "CONFIRMED",
  "rules": [
    {
      "id": "smoking-voice",
      "name": "抽烟报警固定语音",
      "enabled": true,
      "approvalStatus": "CONFIRMED",
      "priority": 80,
      "match": {
        "alarmTypeIds": ["62"],
        "alarmNames": ["抽烟报警"],
        "alarmAliases": [],
        "vehicleTypes": [],
        "companyIds": [],
        "companyNames": [],
        "timeRanges": []
      },
      "action": "AUTO_VOICE",
      "voiceTemplateId": "voice-smoking-v1",
      "audioAssetId": "audio-smoking-v1",
      "allowRealIntercom": true,
      "requireVehicleAllowlist": true,
      "failureAction": "MANUAL_REVIEW",
      "updatedAt": "2026-07-18T00:00:00.000Z",
      "changeNote": "经业务方确认"
    }
  ]
}
```

当前运行时动作枚举：

- `AUTO_VOICE`：通过全部安全闸门后演练或真实播放固定音频。
- `MANUAL_REVIEW`：值班人员接管。
- `RECORD_ONLY`：只留痕，不执行外部动作。
- `DISABLED`：规则停用，按转人工处理。

目标 V2 响应模型：

```text
handlingMode = AUTO / MANUAL / RECORD_ONLY / DISABLED
channels = TEXT / VOICE
orchestration = SINGLE / SEQUENTIAL / PARALLEL / FALLBACK
```

`AUTO_VOICE` 将迁移为 `handlingMode=AUTO + channels=[VOICE]`；文本提醒使用已审核固定文本模板，不允许生产模式自由生成内容。

## 4. 匹配与冲突

1. 只使用 `enabled=true` 且 `approvalStatus=CONFIRMED` 的规则。
2. 报警类型ID精确匹配优先于名称和别名。
3. 企业、车型、时段条件越具体，优先级越高。
4. 之后按显式 `priority` 降序。
5. 排序权重完全相同的多条规则视为冲突，输出 `MANUAL_REVIEW`。
6. 无匹配、字段不足或规则未确认时输出 `MANUAL_REVIEW`。

规则导入前校验格式版本、规则数量、重复ID、字段类型、时间段、动作枚举、自动语音话术、音频引用与确认状态，以及已确认规则的同条件同优先级冲突。校验失败不替换现行版本。

风险条件字段 `match.risks` 目前只保留在通用模型规划中，尚未形成由业务方确认的字段、运算符和空值语义。当前运行时会拒绝导入非空风险条件，而不是忽略条件继续匹配；取得正式规则表后再增加版本化运算符并补回归测试。

## 5. 事件归并与状态机

业务唯一键优先使用平台报警记录ID；没有ID时使用“车辆ID/车牌 + 报警类型ID/名称 + 报警时间”的稳定哈希。兜底键字段不完整时标记为弱身份，等待后续接口补齐。

```text
DISCOVERED → READY → RULE_MATCHED → EXECUTING / MANUAL_REQUIRED / RECORD_ONLY
           → SUCCEEDED / FAILED / UNKNOWN → RECORDED
```

同一字段出现不同非空值时保留原值并记录 `conflicts`；来源记录包含抓取ID、接口规则和采集时间。

## 6. 对讲编排

### 演练适配器

校验规则、音频和动作状态，生成 `SUCCEEDED` 演练记录，但不调用省平台、不建立WebSocket。

### 平台适配器

当前仓库只保留平台适配器边界、安全闸门和阻断结果，不包含会调用省平台动作接口的生产实现。获得客户明确授权并完成测试车辆抓包验证后，再按下述目标调用链实现。

真实动作必须经过规则许可、真实模式、车辆白名单、确认音频和已验证调用链。适配器在页面主世界复用当前登录态：

1. 启动接口取得WebSocket地址和文件名。
2. 按8kHz、16bit、单声道、每帧320采样点发送PCM。
3. 需要时调用保活接口。
4. 播放结束或异常时调用关闭接口。
5. 启动后结果无法确定时写 `UNKNOWN`，不得自动重播。

历史静态JS中的路径只是配置默认值；`verified` 只能在授权测试车辆完成真实验证后开启。

## 7. 固定音频

导入WAV必须是PCM、8kHz、16bit、单声道。插件提取PCM数据并记录SHA-256、时长、导入时间和确认状态。规则引用资产ID，历史动作同时记录资产ID与哈希，保证音频更新后仍可追溯。

目标产品同时管理固定文本模板。文本模板与音频资产均执行草拟、审核、发布和停用流程，配置人不得审核本人提交的版本。

## 8. Excel与JSON

正式Excel模板尚未进入仓库。当前运行时只导入JSON，并可导出带UTF-8 BOM的Excel兼容脱敏CSV和本机技术诊断JSON。目标产品的日报、月报和企业导出在独立报表中心完成；完整JSON作为敏感证据包单独授权和审计。

拿到Excel后新增离线转换器：列名映射到规则字段，长ID按文本读取，生成JSON后调用同一校验器。Excel不是运行时直接查询的数据源，也不持续追加写入用户正在打开的文件。

## 9. 失败兜底

以下情况统一进入人工处理：规则未命中或冲突、音频无效、车辆不在白名单、车辆离线、账号无权限、调用链未验证、启动接口失败、WebSocket失败、关闭失败、页面关闭或执行结果未知。

动作失败不删除原始事件，不自动重播，并写入动作记录和台账。
