### 文本模板列表

```http
POST /api/base-service/messageTemp/listPage
```

请求体：

```json
{
  "pageNum": 1,
  "pageSize": 20
}
```

实测响应摘要：

```json
{
  "success": true,
  "errCode": null,
  "errMessage": null,
  "total": 0,
  "dataCount": 0
}
```

结论：当前账号下文本模板为空。插件一期可以先内置业务规则话术，后续再支持同步或写入平台模板。

### 未处理报警计数

空请求体返回：

```json
{
  "success": false,
  "errCode": "SYS_ERROR",
  "errMessage": "开始时间不能为空,结束时间不能为空,管理机构业户ID不能为空"
}
```

从前端调用定位到必需参数：

```json
{
  "alarmQueryStartTime": "YYYY-MM-DD 00:00:00",
  "alarmQueryEndTime": "YYYY-MM-DD 23:59:59",
  "groupId": "<当前用户机构ID>"
}
```

使用 `groupId=08` 做只读探测，响应结构为：

```json
{
  "success": true,
  "data": {
    "totalCount": 0,
    "unDealCount": 0
  }
}
```

结论：插件不能硬编码机构 ID，应从登录用户上下文、当前筛选条件或组织树选中节点获取。

## 插件建设建议

1. 以路由为边界：`#/vehicle-monitor/real-time` 做实时报警捕获，`#/alarm-center/alarm-recorde` 做历史查询和补字段，报表中心页面单独做导出辅助。
2. 数据优先走接口拦截：监听 `fetch/XMLHttpRequest` 的请求和响应，记录 payload、响应摘要、时间和当前路由。
3. DOM 只做定点监控：监控报警弹窗、查岗弹窗、文本下发弹窗和详情弹窗，不做全页扫描。
4. 侧边栏展示要和原平台解耦：插件只读平台数据，自己的处置状态、规则命中、话术和人工备注保存到助手本地/后台。
5. 所有外部动作必须有确认：文本下发、对讲控制、查岗响应、报警忽略、正报/申诉都不能静默自动执行。
6. 报警处理必须记录失败：接口失败、参数缺失、麦克风拒绝、WebSocket 关闭、按钮找不到、页面结构变化都要入日志。
7. 组织关系不要完全信平台树：省平台组织树可作为底表，但集团、分公司、企业口径仍需业务方 Excel 校准。

## 语音对讲按钮自动触发可行性

本次根据页面标注按钮和实时监控页懒加载 JS 继续确认：右侧车辆详情区的 `语音对讲` 可以被浏览器插件触发，但它是实时对车辆发起音频通道的业务动作，不能无确认静默执行。

### 按钮条件

按钮来自实时监控页 `RightAside` 组件，条件如下：

| 条件 | 说明 |
| --- | --- |
| 车辆在线 | `currentCarInfo.onlineStatus == 1`，否则按钮禁用。 |
| 当前测试账号有权限 | 权限码 `synthetic-permission-code`。 |
| 未在对讲中 | `intercom.modalShow == false`。 |
| 未在加载对讲 | `isLoadingIntercom == false`。 |

按钮点击调用 `sendIntercom()`，核心请求体：

```json
{
  "cameraIds": [1],
  "carId": "<当前车辆ID>",
  "streamType": 0,
  "subCode": 2
}
```

该请求走：

```http
POST /api/schedule-service/sendVideo/sendRealAudioTransmissionMessage
```

成功后前端读取响应里的：

```json
{
  "httpUrl": "<WebSocket对讲地址>",
  "fileName": "<对讲文件名>"
}
```

然后打开 `Intercom` 组件，申请麦克风权限，并把浏览器采集到的音频通过 `httpUrl` WebSocket 发出去。

### 关闭和保活

| 动作 | 接口 | 参数要点 |
| --- | --- | --- |
| 关闭对讲 | `/api/schedule-service/sendVideo/sendRealAudioControlMessage` | `cameraIds:[1]`、`carId`、`filename`、`subCode:4`、`closeType:0`。 |
| 继续/保活 | `/api/gpsp-service/sendVideo/sendRealAudioKeepMessage` | `carId`、`filename`、`streamType:"0"`、`subCode:"0"`、`result:1`。 |

### 自动播报实现判断

| 方案 | 可行性 | 说明 |
| --- | --- | --- |
| 插件触发原按钮 | 可行 | 内容脚本可在车辆选中且按钮可用时点击原按钮。最少改动，但依赖页面 DOM 和麦克风权限。 |
| 插件直接调同接口 | 可行 | 复用 `sendRealAudioTransmissionMessage` 获取 `httpUrl/fileName`，再建 WebSocket。比点按钮稳定，但需要自己实现关闭/保活/失败处理。 |
| 自动播报 TTS | 可行但需实测 | 平台组件发送的是 8kHz、16bit、单声道 PCM，320 采样点一帧。插件/后台可以把固定话术 TTS 转成同格式后发 WebSocket。 |
| 用系统扬声器让麦克风收音 | 不建议 | 容易有回声、噪声、音量不稳定，只适合作为临时演示兜底。 |

### 推荐一期做法

1. 监听报警接口或弹窗，拿到 `carId`、车牌、报警类型。
2. 自动进入 `#/vehicle-monitor/real-time`，定位并选中对应车辆。
3. 确认车辆在线、按钮可用、账号有对讲权限。
4. 自动生成固定话术，先弹出确认面板。
5. 用户确认后触发对讲按钮或同接口，开始播报。
6. 记录开始时间、结束时间、接口结果、WebSocket 状态、失败原因和话术文本。

自动“无人确认直接喊话”技术上可做，但一期不建议默认开启；应至少按企业/报警类型配置白名单，并保留人工确认开关。

## 当前判断

省平台已经暴露了插件一期所需的大部分数据入口：报警类型、实时报警、报警查询、车辆组织、车辆详情、文本下发组件、对讲组件和查岗列表都能定位。主要缺口不是“有没有接口”，而是几个动作类接口的真实参数、弹窗 DOM、报表口径，以及哪些动作允许自动执行。

一期插件建议先做“捕获、补字段、规则提示、人工确认、处置留痕、报表辅助”，不要直接做无人值守自动处置。
