# 三客一危值班助手：角色权限与职责分离设计

版本：`1.0`  
形成日期：`2026-07-19`

## 1. 目标

通过角色权限、企业数据范围和同一业务对象上的职责分离，避免监控人员同时配置并审核规则、规则配置人员自审自发、管理员天然拥有全部业务权限等风险。

## 2. 权限由三部分共同决定

```text
最终权限 = 功能角色权限 ∩ 组织/企业数据范围 ∩ 数据敏感级别权限
```

例如，报表员拥有“生成月报”权限，但只能对其授权企业生成；监控值班员能查看本班报警，但默认不能导出完整敏感 JSON。

助手系统身份与省平台登录账号是两套权限。助手身份决定角色、企业范围和敏感级别；省平台账号决定页面与动作能力。真实文本/语音动作必须两边都允许，审计同时记录实名助手用户与省平台账号的可追溯标识，但不保存密码、Cookie 或 Token。

## 4. 强制职责分离规则

1. `rule.createdBy != rule.reviewedBy`。
2. 同一自然人不得同时拥有监控值班员、规则配置员和规则审核员三项生产权限；监控值班员不得兼任生产规则审核员。
3. 规则配置员提交审核后不能直接修改待审版本；修改必须撤回或生成新草案。
4. 规则审核员不能审核自己参与配置的同一版本。
5. 监控值班员不能修改正在运行的规则、模板和真实动作白名单。
6. 高风险人工处置的执行人与复核人不能相同。
7. 系统管理员不能通过技术管理权限自动获得规则审核、处置和敏感导出权限。
8. 敏感证据包的导出人不能删除对应审计记录。

## 5. 企业数据范围

- 用户可以绑定一个或多个组织节点或企业。
- 组织树继承必须可配置，不能默认查看所有下级。
- 集团汇总和企业明细使用不同权限。
- 车辆归属变化时保留事件发生时的企业快照，不能用当前归属重写历史报表。
- 跨企业对比、排名和下钻分别授权。

## 6. 替岗和值班交接

- 值班账号必须实名到人，不使用多人共享账号记录插件业务操作。
- 无法避免省平台共享账号时，仍必须由实名助手用户认领班次；身份无法确认时禁止真实动作和敏感导出。
- 替岗需要明确开始、结束时间和授权范围。
- 交接时列出未完成 ManualTask、进行中动作、异常接口和待复核处置。
- 交接不能改变报警原始事实和已产生的动作记录。

## 7. 审计要求

至少记录：用户、角色、企业范围、时间、终端、业务对象、操作前后值、理由和结果。

关键审计事件：规则提交/审核/发布/回滚、真实文本/语音动作、人工重试、处置完成/复核、企业范围变更、报表生成、敏感导出和下载。
