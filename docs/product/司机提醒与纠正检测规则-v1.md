# 三客一危值班助手：司机提醒与纠正检测规则 V1

版本：`1.0`  
日期：`2026-07-21`  
适用：规则中心 Schema V2、扩展 `0.5.4` 及以上

## 1. 总原则

- 不默认同时发送文本和语音；每条规则必须明确主渠道和是否允许第二渠道。
- 官方要求即时人工干预或喊话的报警：语音对讲为主渠道；文本只能由规则明确配置为失败兜底或成功后的补充。
- 需要司机即时纠正的驾驶行为类报警：语音优先。
- 设备类、调度类、事后类报警：默认内部确认，不自动向司机喊话。
- 所有文本和语音均引用已审核、已发布的固定资产，不允许插件临时生成自由话术。
- 报警升级、持续时长、解除和平台状态由省平台判定；插件不通过视频或本地启发式替代平台判断。
- 省平台字段、视频状态或客户 SOP 不能明确证明完成时，写入 `UNKNOWN_MANUAL` 并生成值班人工待办。

## 3. 运行策略字段

每条已发布规则可增加：

```json
{
  "reminderPolicy": {
    "category": "DRIVER_IMMEDIATE",
    "driverReminder": "VOICE_REQUIRED",
    "secondaryChannelMode": "ON_PRIMARY_FAILURE",
    "completion": {
      "source": "PLATFORM_STATUS",
      "fields": ["alarmStatus", "alarmCompleteStatus", "platformStatus"],
      "clearedValues": {
        "alarmStatus": ["平台确认的解除值"],
        "alarmCompleteStatus": ["平台确认的完成值"]
      },
      "unknownAction": "MANUAL_REVIEW"
    }
  }
}
```

### `driverReminder`

- `VOICE_REQUIRED`：主渠道必须为 `VOICE`。
- `VOICE_PREFERRED`：主渠道必须为 `VOICE`，适用于需要即时纠正的驾驶行为。
- `TEXT_ONLY`：仅用于明确批准的文本/TTS规则或本机沙箱演练。
- `INTERNAL_ONLY`：不自动触发司机提醒，必须使用人工工单。
- `VOICE_OR_TEXT_PENDING`：渠道尚未确认，禁止自动发送，统一转人工。

### `secondaryChannelMode`

- `NONE`：不启用第二渠道，默认值。
- `ON_PRIMARY_FAILURE`：主渠道明确失败后才执行第二渠道；结果未知、超时或被阻断时禁止切换。
- `AFTER_PRIMARY_SUCCESS`：主渠道明确成功后才执行规则明确配置的补充渠道。
- `MANUAL_ONLY`：第二步只能由值班人员操作。

当前系统允许显式配置“语音主渠道 + 文本/TTS第二渠道”，但不会因为语音失败就自动无限重试或自动改走其他渠道。文本和语音的每次结果都单独留痕。

## 4. 完成判定状态

插件只读取配置的省平台字段，不自行分析视频或推断报警解除：

- `PLATFORM_CLEARED`：字段值命中规则配置的已解除/已完成值。
- `PLATFORM_ACTIVE`：平台仍提供状态，但没有命中解除值；不代表插件完成判定。
- `UNKNOWN_MANUAL`：字段缺失、状态口径未配置、证据冲突或只允许人工确认；生成人工待办。

动作成功后，如果后续平台状态仍为 `PLATFORM_ACTIVE` 或 `UNKNOWN_MANUAL`，服务器生成未完成/无法判断人工工单；只有 `PLATFORM_CLEARED` 才能结束提醒后的确认阶段。

## 5. 不在本规则内的能力

- VLM 视频纠正判断不作为首版自动通过依据。
- 司机录音、回复识别和转写默认关闭。
- 超速持续多久、停车多久、夜间异动阈值等由省平台或客户 SOP 提供，未确认前只保存原始平台状态和人工结果。
- 预报警 `PREWARNING` 只实时抓取、展示和入库，不触发司机自动提醒。
