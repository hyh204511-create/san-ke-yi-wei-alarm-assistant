## 一句话判断

客户不是要重建一个监管平台，而是要一个叠加在现有省平台上的网页小助手：先把报警出现后的第一处置动作标准化、可提醒、可留痕，再把报警查询、联网联控、报表中心里的数据整理成可下载月报和排名表。

## 客户真实目标

| 维度 | 当前判断 |
| --- | --- |
| 表面需求 | AI 报警处置助手、语音提醒、报警处理记录、报表中心、月报下载。 |
| 真实目标 | 降低值班人员盯屏、筛选、提醒、复制、统计和报表整理成本，减少漏处置和无法追溯。 |
| 验收关注 | 报警能不能及时抓到，是否能按规则提醒司机，是否能记录处理过程，月报/排名表能不能按集团和分公司导出。 |
| 决策压力 | 业务方需要给周总/企业看得懂的方案和后续可演示成果，不只是技术原型。 |
| 隐含矛盾 | 平台数据可查但分散；企业组织关系不稳定；部分报表字段口径不清；自动通过查岗弹窗有风控风险。 |
| 我方切入点 | 不替代省平台，只做浏览器插件式辅助；先用现有页面和接口把高频人工动作收敛。 |

## 核心需求拆解

### 1. 报警第一处置

| 需求 | 插件处理方式 | 当前可用信息 |
| --- | --- | --- |
| 实时捕获报警 | 监听实时监控页报警弹窗和未处理报警接口，列表兜底。 | `getVideoUnprocessedAlarm` 已记录；实时无报警时返回空数组，有报警时返回报警详情。 |
| 识别报警类型 | 拉取报警类型配置，建立 `alarmId -> alarmName` 字典。 | `alarmUserSet/listAll` 已记录，抽烟报警为 `alarmId=62`、`alarmSource=2`。 |
| 读取报警详情 | 通过报警查询接口补齐车牌、企业、司机、时间、位置、图片、视频和状态。 | `alarmQueryList` 已记录，2026-06-30 查询返回 `total=58`。 |
| 读取车辆/组织 | 根据 `carId` 查询车辆详情，按组织树建立集团/企业/车辆归属。 | `loadAllVehicleGroupTree`、`getMonitorCarInfo/{carId}` 已记录。 |
| 匹配规则和话术 | 使用报警类型、车辆类型、企业规则匹配固定话术，不自由发挥司机喊话。 | 需要业务方提供规则 Excel 和话术模板。 |
| 语音提醒/对讲 | 使用省平台已有对讲组件和 WebSocket 音频通道。 | 对讲 JS 已记录，确认前端采集麦克风并通过 WebSocket 发送 8kHz 单声道音频。 |
| 留痕和复盘 | 保存报警原始字段、规则命中、话术、对讲开始/结束、失败原因、人工介入。 | 需要建设助手自己的处理记录表。 |

### 2. 人工协同

| 需求 | 插件处理方式 | 边界 |
| --- | --- | --- |
| 无法自动处理时提示人工 | 对高风险、低置信度、接口失败、按钮不可用、对讲失败生成待办。 | 不静默失败。 |
| 企业通知话术 | 根据报警、车辆、企业、司机和处理动作生成可复制文本。 | 一期先辅助复制，不强制自动发外部消息。 |
| 值班人员通知 | 对未纠正、无法判断、高风险报警通知值班人员。 | 短信/企微/电话网关需另行确认。 |
| 申诉/误报处理 | 读取平台状态，记录“申诉通过、报警申诉、已处理”等状态。 | 不替业务方最终判断正报/误报。 |

### 3. 报表中心

| 需求 | 插件/后台处理方式 | 当前状态 |
| --- | --- | --- |
| 月报优先 | 先按月拉取报警查询、联网联控、报表中心数据，套固定模板。 | 报警查询接口已记录；联网联控和报表中心接口待抓取。 |
| 按集团/分公司/企业导出 | 建立集团、分公司、企业、车辆关系表，再聚合报警和轨迹数据。 | 车辆组织树可提供省平台现有层级，但集团关系仍需业务方 Excel 校准。 |
| 违法明细/排名 | 从报警查询里筛选真实报警、违法报警、超速/超时/夜间违规等。 | 状态映射和违法率公式待确认。 |
| 轨迹完整率排名 | 从联网联控轨迹完整率明细抓低于 100% 的车辆并排名。 | 页面和接口待采集。 |
| 行驶里程/千公里报警数 | 拉取或计算里程、报警次数、分母口径。 | 字段来源未确认。 |

### 4. 查岗/风控弹窗

| 需求 | 推荐处理 |
| --- | --- |
| 发现查岗弹窗 | 插件监控弹窗出现，截图、记录时间、通知值班人员。 |
| 夜间无人值守 | 通知手机远程处理，或切备用已部署电脑。 |
| 自动答题 | 一期不默认做。自动通过可能触发平台风控，需客户明确授权并验证风险。 |

## 网页小助手建议处理流程

1. 插件常驻省平台登录页面，识别当前路由：实时监控、报警查询、报表中心、联网联控。
2. 拉取报警类型配置，缓存 `alarmId`、报警名称、来源、是否开启提示音。
3. 在实时监控页监听报警弹窗，同时轮询或订阅未处理报警接口。
4. 捕获报警后，用 `carId` 查询车辆详情，用组织树补齐企业归属。
5. 调用规则引擎：报警类型、车辆类型、企业规则、时间段、速度、状态共同决定动作。
6. 动作只分四类：语音对讲、文本/话术提醒、内部确认、暂不自动处理。
7. 执行动作前生成固定话术，执行后记录结果；对讲失败、麦克风失败、WebSocket 关闭都记为失败原因。
8. 对未纠正、无法判断、高风险、接口失败、按钮不可用的报警生成值班人员待办。
9. 报表模块按月批量拉取报警查询、联网联控、报表中心数据，按组织关系聚合后导出 Excel/PDF。
10. 查岗弹窗只做监控、截图、通知，不默认自动答题。

## 一期应收敛的 Done when

| 能力 | Done when |
| --- | --- |
| 报警捕获 | 插件能在实时监控页捕获报警，并能从接口补齐同一条报警核心字段。 |
| 类型识别 | 报警类型字典可自动拉取，规则里可选择抽烟、未系安全带、超速、超时等类型。 |
| 语音提醒 | 能对选定报警生成固定话术，打开或复用省平台对讲能力，并记录成功/失败。 |
| 处置留痕 | 每条报警能查到原始字段、规则命中、话术、动作、失败原因和人工备注。 |
| 人工升级 | 高风险、失败、无法判断场景能生成待办或通知值班人员。 |
| 月报模拟 | 选定 5 月数据，至少完成一张集团/分公司月报的字段来源验证和导出样表。 |
| 查岗监控 | 能识别查岗弹窗并截图通知，不要求自动通过。 |

## 当前风险判断

1. 不要把一期卖成“全自动无人值守”，会议纪要明确一期价值是先提醒和留痕。
2. 不要把报表做成只看不下的网页，业务方短期需要能下载、能留档、能转发的电子报表。
3. 报表最大风险不是模板，而是数据来源和计算口径不清。
4. 省平台组织树可用，但企业实际集团/分公司关系可能需要业务方单独维护。
5. 查岗弹窗不能默认自动通过，应先做监控和通知。
6. 浏览器插件要把失败当成一等状态记录，尤其是接口失败、页面结构变化、对讲失败、麦克风权限失败。
