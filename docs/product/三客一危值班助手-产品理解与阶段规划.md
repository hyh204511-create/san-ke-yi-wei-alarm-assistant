# 三客一危值班助手：产品理解与阶段规划

> 2026-07-19 说明：本文件已按多角色、职责分离、多通道响应、独立报表中心和敏感数据治理要求升级。完整产品逻辑以 [产品逻辑规划 V2](三客一危值班助手-产品逻辑规划-v2.md) 为准。

## 1. 产品定位

产品是叠加在现有省平台之上的报警处置与数据治理辅助系统。浏览器插件负责平台侧采集、提示和受控动作适配；规则审核、日报月报、企业数据范围和敏感导出需要独立产品模块，不能全部交给一个值班人员或一个插件设置页完成。

## 2. 目标角色

- 监控值班员：报警监控、人工接管、备注和处置。
- 班组负责人/处置复核员：高风险处置复核和班组待办。
- 规则配置员：规则、文本模板和语音模板草案。
- 规则审核员：审核、批准、发布和回滚；不能审核本人配置的版本。
- 数据分析/报表员：授权企业的数据展示、日报和月报。
- 系统管理员：用户、组织、企业范围和技术配置。
- 安全审计员：规则、动作、处置、导出和敏感访问审计。

## 3. 产品域

| 产品域 | 核心能力 |
| --- | --- |
| 监控与处置 | 报警发现、字段补齐、规则判断、文本/语音响应、失败转人工 |
| 规则治理 | 草拟、仿真、审核、发布、回滚和版本追溯 |
| 数据与报表 | 企业展示、处置台账、日报、月报和授权导出 |
| 审计与安全 | 角色、企业范围、职责分离、敏感数据和导出审计 |

## 4. 核心调整

- 不再把产品定义为只有一个值班人员。
- 监控操作、规则配置、规则审核和敏感导出分权。
- 处理策略与响应渠道分离，支持文本、语音和组合策略。
- 日报、月报和企业数据展示建设为独立报表中心。
- 普通导出默认聚合或脱敏；完整 JSON 改为受控敏感证据包。
- 现有字段来源、业务去重、失败转人工和演练/真实隔离继续保留。

## 5. 当前实现边界

当前仓库已经实现浏览器采集、事件归并、规则运行时、多角色身份、规则审批、文本/语音资产治理、演练/沙箱动作、人工处置、企业日报月报、加密本机台账和敏感证据包审批。真实平台生产适配、正式报表口径、数据库全字段保护和外部不可抵赖审计仍属于后续工作。

真实文本与语音动作仍需授权账号、测试车辆、固定模板和真实平台链路验证；当前生产动作固定阻断。
