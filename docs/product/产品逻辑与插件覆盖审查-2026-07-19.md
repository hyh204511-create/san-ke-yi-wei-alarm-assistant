# 产品逻辑与插件覆盖审查

审查日期：`2026-07-19`  
审查范围：浏览器插件、本机采集服务、Django 身份与治理模块、人工处置、响应资产、日报月报、敏感证据包及产品文档。

## 1. 总体结论

产品逻辑方向正确，且已经按本次要求完成结构性调整：

- 产品不是单一值班员工具，监控、处置复核、规则配置、规则审核、报表、系统管理和安全审计使用独立角色。
- 监控、规则配置和规则审核账号互斥；规则创建人不能审核本人版本。
- 实时报警和技术检测优先；预警与历史查询只记录，不进入实时自动动作队列。
- 文本和语音都是正式响应渠道，可单独、顺序、并行或兜底编排。
- 日报、月报及企业导出位于独立报表中心，不在值班插件中提供。
- 完整 JSON 按 L4 高敏证据处理，普通插件和普通报表均不提供 JSON 导出。
- 字段来源追踪、跨接口归并、冲突保留、失败转人工和演练/真实动作分离均保留。

当前不能认定为生产功能全覆盖。主要原因不是本地治理流程缺失，而是真实省平台接口、字段、企业编码、文本/语音成功回执和长时间运行合同尚未完成只读与授权联调。生产动作继续保持硬阻断是正确的。

## 3. 本轮代码审查发现并修复的问题

1. 加密密钥环境判断原先依赖 Django `DEBUG`。测试运行器会临时关闭 `DEBUG`，导致加密字段误判为生产缺密钥。现改为显式 `ALLOW_DERIVED_DATA_KEYS`；生产必须关闭派生并提供独立密钥。
2. 证据审批和工单复核接口原先使用 `bool(value)`，字符串 `"false"` 会被当作批准。现只接受 JSON 布尔值。
3. 角色互斥原先只禁止监控兼规则审核，仍允许规则配置与审核落在同一账号。现监控、规则配置、规则审核三类生产角色两两互斥。
4. 本机采集器原先把完整抓取和事件明文写入 JSONL。现改为 AES-256-GCM 加密的 `.encjsonl`，缺少密钥时拒绝持久化。
5. 浏览器离线队列原先可能长期保存完整抓取。现原始抓取不进入浏览器持久队列，标准事件缓存限制为 200 条和 24 小时。

## 4. 敏感数据审查

已达到的边界：

- 密码、Cookie、Authorization、Session、Token、手机号和身份证类字段会从证据包递归遮盖。
- 完整 JSON 只能通过证据申请流程获得加密文件；申请人与审批人必须不同。
- 证据文件带内容哈希、下载次数、过期时间和删除审计。
- 生产环境要求 `SENSITIVE_DATA_KEY`、`EVIDENCE_MASTER_KEY`、`COLLECTOR_DATA_KEY` 三类用途不同的密钥。

仍需强化：

- 数据库中的部分检索标识和展示标量仍为明文，例如事件 ID、报警 ID、车牌快照、平台账号引用和企业名称。完整 JSON 快照已加密，但这不等于数据库全字段加密。
- 浏览器 `chrome.storage.local` 是短期运行缓存，不具备独立密钥隔离能力；生产终端仍需操作系统账号隔离、磁盘加密、浏览器配置保护和自动锁屏。
- 审计表是应用级追加记录，尚未采用 WORM、外部日志留存、签名或哈希链，不能宣称强不可抵赖。
- 报表与证据文件目录需要生产级访问控制、备份、密钥轮换和灾备制度。

## 5. “最新报警无法抓取”的判断

页面已确认存在“技术检测”“实时报警”“预警列表”三个独立页签。真实流量进一步证明 `alarmQueryList` 是查询/核验/申诉共用历史接口，并非预警专用接口，已经改为 `HISTORY`。预警专用接口仍需在插件 0.3.1 重新加载后通过只读发现规则确认。

真实平台需要验证：

- 三个页签首次加载、刷新、分页、筛选和切换时分别调用哪些接口。
- 最新数据是否来自 `fetch/XHR`，或改用了 WebSocket、SSE、Service Worker、页面缓存或新接口。
- 报警弹窗、数量角标和表格明细是否来自同一数据源。
- 登录续期、断线重连、接口前缀变化和响应嵌套变化。
- 运行至少一个完整值班周期后的漏抓、重复、延迟和内存占用。

在上述只读合同验证前，不应开启真实文本、语音、忽略、正报、申诉或查岗响应。

## 6. 尚未全覆盖的产品能力

- 真实省平台文本与语音适配器、成功/失败/未知回执判定。
- 真实企业 ID、名称和集团/分公司权威关系校准。
- 工单超时升级、交接班队列、班组调度和批量处理。
- 日报/月报正式模板、指标口径、截止时间、迟到补数时限和接收对象。
- 企业趋势、排名、重复高风险车辆和数据质量专题看板。
- 数据库全部敏感标量加密或令牌化、密钥轮换和外部不可抵赖审计。
- 真实平台长时间只读回归及授权测试车辆动作验收。

## 7. 最终判断

- 产品逻辑：正确，已消除“单一值班人员”“语音单渠道”“插件内报表导出”和“完整 JSON 普通下载”四个核心偏差。
- 插件边界：正确，负责采集、优先级、当前待办和受控动作适配，不承担规则审批、正式报表和敏感导出治理。
- 本地功能覆盖：主体治理闭环已经形成，适合作为受控测试版本。
- 生产功能覆盖：未完成。真实平台合同、企业映射、正式报表口径、生产数据安全和真实动作联调仍是上线阻断项。
