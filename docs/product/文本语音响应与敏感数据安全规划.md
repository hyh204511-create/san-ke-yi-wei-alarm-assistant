# 三客一危值班助手：文本、语音响应与敏感数据安全规划

> 本文件中的早期组合示例已经废止。当前执行规则以《三客一危值班助手-最新规则逻辑-v8》和服务器计划部署书 V3 为准：自动规则只能配置一个 `TEXT_TTS` 或一个 `VOICE_INTERCOM` 渠道，不能在两个渠道之间自动切换。

> 2026-07-21 需求确认后更新：`VOICE_INTERCOM` 表示 AI 自动触发省平台语音通道并播放固定语音，不是人工实时通话；当前没有测试车辆，真实适配器继续阻断。`TEXT_TTS` 表示文本下发并要求终端 TTS 播读。明确失败可按5秒、10秒重试，30秒内转人工；超时和结果未知不重试。司机回传录音/转文字暂不启用，待授权、隐私和技术联调确认。

版本：`1.0`  
形成日期：`2026-07-19`

## 1. 响应模型

目标规则不再使用单一“自动语音”表达全部响应，而是拆分：

```text
处理策略 handlingMode
+ 响应渠道 channels
+ 渠道顺序 orchestration
+ 固定模板 templates
+ 失败兜底 fallback
```

示例：

```json
{
  "handlingMode": "AUTO",
  "channels": [
    {"type": "TEXT", "templateId": "text-identity-v1", "order": 1},
    {"type": "VOICE", "assetId": "audio-identity-v1", "order": 2, "when": "TEXT_FAILED_OR_HIGH_RISK"}
  ],
  "fallback": "MANUAL_REVIEW"
}
```

## 2. 文本提醒

- 只使用已审核固定文本模板。
- 必须明确接收对象类型与目标标识；车载终端、司机账号、企业联系人和平台站内对象不能混为同一渠道。
- 模板记录版本、适用报警、企业范围、有效期和审核人。
- 运行时变量只允许从白名单字段填充，禁止任意脚本或 HTML。
- 下发前校验车辆、报警、模板和页面会话。
- 记录请求、平台回执、失败原因和最终状态。
- 没有明确回执时写 `UNKNOWN` 并转人工。

在真实平台契约确认前，“文本提醒”只表示一种待适配渠道，不能默认等同于已向司机成功送达。

## 3. 语音提醒

- 只使用已审核固定音频。
- 校验采样率、位深、声道、时长和 SHA-256。
- 音频更新生成新版本，历史动作保留旧哈希。
- 真实执行必须通过模式、白名单、权限、在线和并发闸门。
- AI 自动触发平台语音通道并播放固定语音；不把该动作描述为人工实时通话。
- 启动、WebSocket、保活、关闭分别记录结果；没有测试车辆前只能运行沙箱适配器。
- 失败或不确定不自动重播；明确失败才允许5秒、10秒短重试，30秒内转人工。

## 4. 文本和语音组合

| 场景 | 建议策略 | 说明 |
| --- | --- | --- |
| 一般提醒 | 规则指定单一渠道 | 不在文本和语音之间自动切换 |
| 高风险报警 | 规则指定 `VOICE_INTERCOM` 或转人工 | 由审核规则决定 |
| 文本失败 | 重试后转人工 | 不自动切换到语音 |
| 语音失败 | 重试后转人工 | 记录启动/播放/关闭结果 |
| 状态未知 | 直接人工 | 防止重复提醒司机 |
| 设备技术报警 | 记录或通知值班人员 | 通常不向司机发送语音 |

## 5. 模板治理

文本模板和语音资产都执行：

```text
DRAFT → IN_REVIEW → APPROVED → PUBLISHED → RETIRED
             ↘ REJECTED
```

配置人与审核人分离。模板发布后不可覆盖，只能创建新版本。规则只能引用 `PUBLISHED` 模板。

## 6. 敏感数据分类

| 数据 | 敏感性 | 产品处理 |
| --- | --- | --- |
| 报警类型和汇总数量 | 内部业务 | 可进入授权报表 |
| 企业名称和处置率 | 内部业务 | 按企业范围展示 |
| 车牌和车辆 ID | 敏感明细 | 页面按权限显示，普通导出掩码 |
| 司机姓名和身份信息 | 高敏个人信息 | 最小化采集，严格范围和审计 |
| 精确位置、轨迹和时间 | 高敏业务信息 | 最小范围、限制导出和保留期 |
| 值班备注 | 敏感业务信息 | 仅处置链和审计人员可见 |
| 原始响应、视频、图片、证据 URL | 高敏证据 | 受控本地或专用存储，禁止普通导出 |
| Cookie、Authorization、Token、密码 | 禁止采集 | 捕获时脱敏，不落业务存储 |

## 7. 完整 JSON 风险

完整 JSON 往往同时包含车辆、司机、企业、位置、时间、备注、字段来源和原始接口摘要。即使没有密码和 Token，也可能构成高敏业务证据。

因此：

- 普通值班员界面不提供完整 JSON 导出。
- 普通报表只提供聚合或脱敏数据。
- 技术排障采用最小事件范围的敏感证据包。
- 证据包记录用途、审批、文件哈希、下载和删除时间。
- 文件必须避免进入公共下载目录、聊天工具或第三方云盘。

## 8. 数据保留建议

具体期限由客户制度确认，产品需要支持按数据级别配置：

- Capture 原始脱敏证据：短周期排障保留。
- AlarmEvent、Decision、ActionAttempt、Ledger：按监管和项目要求保留。
- 报表快照：按日报/月报归档制度保留。
- 视频、图片和高敏证据：最短必要期限和专用存储。
- 导出文件：设置过期时间，到期删除并保留删除审计。

## 9. 安全验收

- 未授权角色无法查看其他企业数据。
- 规则配置人与审核人不能相同。
- 文本和语音只能引用已发布模板。
- 完整 JSON 不出现在普通导出入口。
- 普通导出默认脱敏。
- 敏感导出包含用途、范围、文件哈希和下载审计。
- Cookie、Token 和密码不进入存储与导出。
- 失败和未知动作不会跨渠道自动切换；未知不重试，明确失败只按固定短重试策略执行。
